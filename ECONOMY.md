# Local Coins economy
Configuration: src/roster.ts. Grants/spending/idempotency: src/economy.ts. Existing credits field and save key retained; schema v4. Old balances convert 1:1 and purchased starting slots remain. Free Maco/Pluma membership follows prior campaign unlocks. Neutro is the starter. Recruit purchases grant permanent access to that roster option for any deployment slot; casualties never consume ownership. Gates remain temporary reinforcements.

First win: 60 + 2 per clear (40 cap) + 10 no-casualty + 10 cooperation. Replays: 20 base plus the same capped clear/bonus rewards. Failed attempts: at least 20 seconds and 3 kills; 1 per kill capped at15. No reward for quitting or early restart. Zip60, Scout90; role upgrades70/110, two ranks. Capacity60, six slots. First win guarantees one recruit. Ten-level automated mixed-squad completion requires no upgrades. Real human balancing/playtesting remains useful.

Every run receives a UUID. Terminal state is settled and saved synchronously before celebration; the transaction, balance, completion and pending receipt share one localStorage write. Reload recovers the pending receipt. Transaction IDs and settled IDs prevent regranting. Purchases use catalog+rank IDs and a UI double-click guard. The save is local, not tamper-resistant or an authoritative paid balance. No payment SDK, accounts, ads, billing, backend or premium currency. Future paid grants require a separately scoped verified backend; these local transaction records are not purchase verification.

Current saves do not checkpoint unfinished patrol simulations; reloading an unfinished run abandons that run without reward. Clearing browser storage removes local progression. Concurrent multi-tab play is not an authoritative synchronized economy.

## Follow-on design direction
Official reference reviewed: Supercell, "New Collection Levels & Mastery Changes" (https://supercell.com/en/games/clashroyale/blog/news/new-collection-levels-and-mastery-changes). Relevant principle: collection progression should be legible and early upgrades should feel attainable. This game's implementation uses visible ownership, bounded role upgrades, clear Coin receipts, and fast first recruitment. It does not copy premium tracks, timed purchase offers, or paid currencies. Future delight work should prioritize legible cell behavior and short nonblocking feedback over more currency systems.
